# Airtable inventory

Every place the website still reads or writes Airtable, or depends on Airtable's shapes, as of `main` at 06f0f1db (2026-11-18). It is the checklist for pauseai-civicrm#1278 and for closing Airtable on 18 Dec: once every **Code** row is gone or switched off, no website code calls Airtable.

Line numbers are for 06f0f1db and drift as PRs merge (#1279 rewrites rows 1, 2 and 13), so each row also names the function or constant. To redo the search on a later `main`:

```sh
grep -rniE 'airtable|app[A-Za-z0-9]{14}|tbl[A-Za-z0-9]{14}|pag[A-Za-z0-9]{14}' src scripts .github static messages template.env package.json netlify.toml
```

"Covered by" names the PR that moves the flow to CiviCRM: #1266 (statement, `STATEMENT_BACKEND`), #1280 and #1281 (national chapters), #1286 (`CRM_URL` and `CRM_KEY`), #1283 (/verify fix), all merged, and #1279 (new signups, `SIGNUP_BACKEND`), open. A flow behind a flag still calls Airtable until the flag is set in Netlify and the Airtable branch is deleted. The repo can't show which flags Production has set, so that column says what the code does when the flag is unset.

## What the uncovered flows need from CiviCRM

None of rows 2 (old `rec` links), 5, 6, 14 and 15 has a CiviCRM API to call yet. The website calls only `PauseaiChapterDetails.publicList`, `PauseaiMemberIntake.submit` and `verify`, and `PauseaiStatement.sign`, `verify` and `publicList`. So none was moved here: moving one would mean inventing an API.

- **/about people (row 5).** An `API4` action like `PauseaiPeople.publicList` (name to be chosen in pauseai-civicrm) answering, per person shown: display name, title, bio, photo URL, privacy flag (show first name only, no photo) and sort order, already filtered to the people marked for /about. The website would then follow `nationalGroups.ts` (`callCrmRows`, a last-good copy for when the CRM is down) behind a flag such as `ABOUT_BACKEND`. Needs the fields to exist on CiviCRM contacts and the /about data imported. A simpler alternative that needs no CiviCRM work: a JSON file in the repo, edited by PR, like `national-chapters.json`, since the list changes a few times a year.
- **Contact us (row 6).** Either an action like `PauseaiContactMessage.submit` (type, message, the sender's name and address, a submission id), recording it as an activity on a matched contact, or dropping the Airtable copy, since the message already reaches the team inbox by email. Separately, **contact-us sends both its emails through MailerSend** (`src/routes/contact-us/+page.server.ts:150`, `MAILERSEND_API_KEY`), so it breaks when MailerSend closes on 11 Dec, a week before Airtable, whatever happens to the Airtable copy.
- **Members verification links sent before the switch (row 2).** `PauseaiMemberIntake.verify` would need to accept `rec` keys for imported Members rows, as `PauseaiStatement.verify` already does for imported signatures, so welcome emails mailed before the switch keep working after 18 Dec. Otherwise those links fail once Airtable closes.
- **Microgrant and stipend forms (rows 14 and 15).** They need a replacement form, such as a CiviCRM form (Afform) or a website form posting to a new action, and somewhere for the applications, which go to Airtable now. An ops decision first: who reads these applications and where.
